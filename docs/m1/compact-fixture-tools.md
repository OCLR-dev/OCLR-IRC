# 精簡工作區與場次工具

設計方向：維持深色、紫色單一重點與緊密資訊層次，讓聊天和右側工具成為主要工作面。

內容配置：移除重複的頂部導覽／版本與底部連線橫列；連線集中側欄帳號。查詢等待改在房間標題的固定位置，右側提供場次來源、本輪圖池與兩隊名單。

互動：查詢提示只切換既定空間的內容，不改變版面高度；沿用 HeroUI 分頁與按鈕回饋，尊重減少動畫偏好。來源更新只同步資料，不送出 IRC 命令；邀請先預覽，再由裁判確認。

此增量使用既有 panel 的已授權讀取資料；逐人邀請另需本人配對、目前已連接的房間、重新讀取場次及房間權限。它不是完整 context、正式出賽名單或批次自動執行。

## 操作及邊界

- 側欄帳號顯示連線狀態，窄視窗以狀態點、懸停標籤及無障礙文字保留資訊；版本仍可在設定的關於頁面查看。
- 房間標題保留固定高度的查詢狀態位置，HeroUI Spinner 與提示僅在等待時出現；完成後聊天輸入、訊息及工具欄的幾何位置不變。
- 工具來源沿用已授權場次清單與輪次 panel，自動訂閱更新，提供手動同步及後續分頁；沒有授權或尚未選取時提供入口。同步、選圖與複製不發出 IRC 命令。
- 圖池按當前輪次的 entry ID 選擇，保留歌曲原名／metadata，使用既有 Main 命令預覽及有限剪貼簿介面。資料過期或規則不允許時停用。
- 兩隊按自己的隊伍 ID 顯示，不推定紅藍、不自動選入替補。已到場依新鮮 settings UID 觀測，未知保持未知。重複 UID／正規化名稱及缺漏來源阻擋邀請。
- 邀請 preview 與 execute 分別重新讀取本人指派（含分頁）及 panel；已核准賽果、取消／撤權、版本或依賴變更、不同配對／relay 連線／房間 epoch 均拒絕。新 IPC 僅接受 team ID／UID／Main token／確認，不接受名稱或 raw command 作為命令來源。
- Main 固定姓名邀請語法並顯示 UID；操作者輸入預覽名稱並確認才送出一次。manual IPC 不能使用網站預覽 token。共用節流、操作互斥與 unknown 人工核對，不會重送。邀請送出、執行效果與玩家到場分開，不因送出而補寫槽位。
- 私人來源僅記憶體，沿用已投影房間的日誌排除及網站操作不落盤。登出／換場清除來源及預覽，不把它存入手動圖池或正式 lineup。

合成測試涵蓋固定版面、900×640、圖池／兩隊名單、來源更新、單次邀請、共同佇列、手動 IPC 隔離、撤權／變更／分頁及私人歷史。實際結果以關聯 PR 與 CI 的確切提交為準；真實 Bancho 回覆／到場、OS provider 與實機 IME 仍另行驗收。
