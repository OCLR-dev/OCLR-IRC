# Lobby 玩家槽位

2026-10-29：參考使用者提供的 Refsu 截圖，將現有 settings 玩家資料改為房間右側的 16 槽列表。未複製 Refsu 原始碼，未新增依賴。

- 顯示槽位編號、玩家名稱、原始 Bancho 狀態、紅／藍隊及房主；Ready 精確比對（不把 Not Ready 計入）。
- 僅在房間仍加入、History 相符且 settings 完整時顯示準備總數及空位。
- 部分、同步中、過期或斷線時缺席槽位顯示「未知」；保留的觀測玩家標示「待核對」。這也表示缺少地圖或 Mods 的部分回覆不會宣稱空位已確認。
- 固定列出 1–16 號，不推斷房間實際容量或鎖定槽位。
- 沿用 Main 的 settings 解析、變更事件後合併查詢、重連同步及過期處理；可使用既有「讀取設定」更新。這是觀測快照，並非遊戲客戶端即時狀態。
- 純讀取顯示；未加入移位、踢人、邀請、隊伍變更等操作。一般頻道與私訊不顯示玩家槽位。

驗證使用本機模擬 IRC，未連線真實 Bancho。介面測試覆蓋 16 槽、兩位玩家（Ready／Not Ready）、14 個空位、房主標示與斷線後不顯示空位；既有重連、OCLR、背景執行測試一併執行。實際玩家狀態格式與各平台實機外觀仍需驗收，不代表 M1 全部完成。

本機結果：`npm run typecheck`、49 項核心測試、完整 `npm run test:ui` 通過；已檢視 `artifacts/player-slots-synthetic.png`，聊天輸入區與右側槽位列表均正常顯示。核心與 UI 測試使用獲准的本機 loopback 執行環境。
