# OCLR-IRC

osu! Chinese League Rookie（OCLR）賽事的裁判用 IRC 桌面客戶端，以 Electron、React 與 TypeScript 開發，使用免費 HeroUI，支援 Windows、macOS 與 Linux。

目前為開發預覽版。IRC 工作區已可使用；OCLR 桌面授權及本機 IRC → 網站投影／命令轉送已接入，已完成部分真實 OAuth／Bancho 房間聯調，尚有回執、撤權與玩家狀態驗收。完整 MVP 與三平台實機驗收尚未完成。

正式應用名稱為 **OCLR IRC**，下載產物以 `OCLR-IRC-*` 命名。內部套件識別、既有本機資料目錄與 OAuth client ID 保持相容。

## 已有功能

- **IRC 登入與聊天**：使用 osu! IRC 專用密碼登入，支援多房間、一般頻道、私訊與名稱補完；可選擇保存本機加密登入憑證。
- **建立與加入比賽房間**：可從已選場次帶入房名；相同來源背景更新時保留草稿並暫停送出。開房成功後自動加入並讀取設定及裁判名單；逾時或斷線不自動重送開房命令。
- **房間狀態與玩家槽位**：顯示地圖、Mods、比賽模式，以及 1–16 號槽位的玩家、隊伍、房主和準備狀態；資料不完整或過期時明確標示。
- **房內快捷操作**：換圖、Mods、立即／延遲開始、一般計時、取消倒數與中止比賽；先核對設定與裁判權限，再預覽及確認送出，不自動重送。
- **比賽狀態與剩餘時間**：收到 Bancho 開賽確認後顯示進行中、歌曲與已知 Mods，並自動讀取一次玩家設定。以官方 osu!standard 譜面及速度 Mods 估算剩餘時間；資料不足保持未知，倒數歸零不代表伺服器已結束。
- **斷線恢復**：恢復連線與房間唯讀查詢，不重送聊天或開房命令。
- **設定與背景執行**：設定頁可選擇關閉視窗後在背景執行；取消勾選後關窗即完整結束。可從系統匣／Dock／工作列恢復，Linux 保留最小化入口。
- **介面語言與關於**：支援簡體中文、繁體中文、英文及跟隨系統，即時切換並保存選擇；關於頁顯示版本、平台與開源授權。
- **OCLR 場次接入層**：已實作系統瀏覽器授權、本人場次、三階段面板與命令預覽／複製；可用性取決於網站端是否提供相應 API。
- **網站 IRC 投影與命令轉送**：將目前房間綁定至本人獲派場次，在網站查看房間訊息並送出支援的 MP 指令；本機核對目標、設定與裁判權限後才傳送。

玩家槽位來自 `!mp settings` 觀測快照，可按「讀取設定」更新；16 個顯示位置不代表房間實際開放容量。房內快捷操作屬手動裁判工作流，送出後需核對 BanchoBot 回覆；啟用網站投影後，可接受綁定場次的網站 MP 指令；未啟用時仍是獨立手動工作區。socket 送出不等於 BanchoBot 確認。

## 開始使用

1. 使用 osu! **IRC 專用密碼**登入，建立或加入比賽房間。
2. 讀取房間設定與裁判名單，核對房間、玩家及 Mods，再使用聊天或房內快捷操作。
3. 如需網站整合，在「連接 OCLR」透過系統瀏覽器授權，選擇本人獲派場次，再按「將目前房間投影到網站」。OCLR 授權與 IRC 登入是兩個獨立連線，IRC 使用者名稱須與 OCLR 帳號相符。
4. 在本機停止投影、切換房間或場次、登出或休眠後，命令轉送會停用；同步失敗須重新綁定，不會自動重送指令。

IRC 密碼與連線由本機管理。啟用投影會把綁定房間的訊息及命令狀態傳至網站；未啟用時可獨立使用 IRC 工作區。詳細授權與命令限制見 [網站 IRC 投影](docs/m1/website-irc-relay.md)。

## 本機開發與執行

需要 Node.js 24+：

```sh
npm ci
npm run dev
```

建立並執行編譯後的版本：

```sh
npm run build
npm start
```

登入使用 osu! **IRC 專用密碼**，不是網站密碼。osu! IRC 目前使用未加密連線。IRC 日誌預設開啟，在安全金鑰服務可用時加密保存七天；「本機日誌」提供開關、範圍檢視／清除及原生對話框匯出（最近 1,000 則）。Linux 仍僅記憶體；無安全服務或寫入失敗不回退明文。IRC 明確登出清除本帳號日誌，退出程式可保留尚未到期日誌。OCLR context 不落盤；本次登入曾啟用網站投影的房間排除本機日誌並清除已存內容，完整逐場歷史驗權待完成。啟用投影時，綁定房間訊息另會傳至網站。本機另保存最小開房防重送紀錄，以及使用者選擇保存的加密 IRC 憑證。

常用驗證與打包命令：

```sh
npm run typecheck
npm test
npm run test:ui
```

介面測試需要桌面顯示環境與本機 loopback 連線；Linux CI 使用 Xvfb。各平台打包命令為 `npm run package:win`、`npm run package:linux`、`npm run package:mac`，輸出於 `release/`；macOS 打包需在 macOS 執行。

## 目前限制

- 完整 MVP、正式 OAuth／Bancho 聯調與三平台實機驗收尚未完成；合成測試不代表真實服務驗收。
- OCLR 關聯歷史驗權、場次恢復記錄、圖池操作計畫與自動核對仍屬待辦，詳見 [桌面端剩餘工作](docs/desktop-backlog.md)。
- 命令已送出不等於已執行；只有支援且相符的 BanchoBot 回覆可自動確認，其餘結果仍須人工核對。未知結果不自動重送。

推送與 `package.json` 版本相符的 `v*` tag，會觸發三平台測試、打包與校驗，通過後發布 GitHub Pre-release。發布要求 macOS Developer ID 簽章與 Apple 公證；也可手動執行不發布的 dry-run。詳見 [Release CI](docs/release-ci.md)。

### 介面文字

GUI 採精簡顯示：保留操作名稱、即時狀態、錯誤、授權比對與操作確認；移除常駐教學、實作備註及說明型懸浮提示。一般聊天顯示「已送出」，MP 指令顯示「執行結果待核對」；前者仍不代表收到伺服器送達回執。操作與資料保存邊界仍以本文件及 `docs/` 為準。

對話類型、房內操作及場次選單使用 HeroUI Select，登入保存與變更確認使用 Checkbox，Mods 使用 Chip。工作區採緊湊配置，未選房間時隱藏空資訊欄；保留鍵盤操作、危險操作確認及 900×640 聊天輸入區。

### 操作記錄與恢復

現有手動變更、開房與網站轉送共用單步操作追蹤。手動操作送出前保存最小恢復記錄（種類、房間、時間與狀態，不含指令或聊天），保存失敗不送出；同房未核對操作會阻擋下一筆一般變更。中止／取消倒數仍須原本權限與節流檢查，可停止追蹤前筆操作後送出；不能取消已交給伺服器的指令。斷線／重啟後待回覆項目改為結果不明，沒有自動重送。

「操作記錄」提供人工核對：停止等待後仍標記結果不明，不假裝成功。已支援的精確 map／abort／aborttimer 回覆顯示「已觀測到對應回覆」，不代表排除外部裁判操作或 exactly-once 保證。其他語義保持待核對。網站操作記錄僅記憶體，換網站身分／場次清除；完整 OCLR 恢復與多步初始化計畫待契約及後續整合。舊開房 guard 仍保守保留未確定歸屬，不冒充 osu UID。

### 裁判常用工具

房內快捷操作可依中文名稱或英文指令搜尋；Cmd／Ctrl＋K 在非輸入區且未組字時只開啟搜尋，不執行指令。選取結果仍使用相同 typed intent、Main gate 與人工預覽確認。聊天區「常用訊息」提供有限模板，只插入草稿且保留原文，最後由裁判自行傳送；草稿不因模板插入而落盤。真實跨平台 IME／輔助工具仍需實機驗收。

OCLR「帳號配對」分別顯示 IRC 暱稱與網站帳號。暱稱相符仍需勾選人工核對，才可啟用網站 IRC 投影與其衍生指令；這不是 IRC UID 證明。重連、改名、登出或切換網站身分會清除核對，晚到回覆不能沿用舊確認。本人場次唯讀查閱不依賴 IRC 配對。正式網站版本、指派與撤權聯調仍待外部驗收。

CI 內測壓縮包會在上傳前核對 SHA256／build identity 並解壓啟動實際成品（獨立空白 profile）。三平台實際結果見對應 commit 的 workflow；此檢查不取代 IME／休眠／安全 provider／升級實機驗收。

開房恢復資料使用 schema 2，按正規化 IRC 暱稱雜湊隔離。舊版未分帳號資料只保留不含房號的未知結果標記，不推定歸屬；每次登入開房前仍須人工核對，不會自動重送。

房內快捷操作新增「連續換圖與 Mods」：明確手動設定、一次預覽，Main 固定房間與版本後逐步送出、讀回核對。失敗／未知／取消／斷線停止後續步驟，不重送或回滾已完成步驟。Freemod 要求個人規則人工確認，NF 不自動加入；目前保留房間既有 ruleset，正式 OCLR 圖池尚未接入。

### 房間設定合成進度（2026-10-30，#8）

已加入 Main 驗證的改名、隊伍／計分／容量、鎖定槽位、房主、密碼及關房預覽。密碼只於確認送出時傳入 Main，預覽與記錄遮罩；關房需輸入完整頻道名稱，離開分頁仍是 PART。所有變更固定房間與 epoch，過期或觀測變動後失效，送出不等於執行成功。合成測試涵蓋各命令、單次確認、秘密隔離及無地圖設定；真實 Bancho 回覆、逐步初始化仍待完成，L04 保持 partial。

### 手動陣容合成進度（2026-10-30，#9）

玩家槽位提供手動 UID 名單、逐人出賽／隊伍／槽位選擇與差異核對。替補不會自動出賽；名稱只供顯示，依 UID 比對。觀測過期不推定到場或缺席。此名單僅目前房間記憶體使用，不是正式 OCLR roster，也不會發送邀請或換人命令。核心與 Electron 合成測試涵蓋相關狀態；正式名單、批次邀請／換人及真實 #UID 行為仍待完成，L05 保持 partial。

### 單筆玩家操作合成進度（2026-10-30，#9）

手動快捷操作新增 invite／move／team／kick。預覽固定 UID、房間及 epoch，移位／分隊／移出只能選擇已核對的房內玩家；邀請不得重複邀請已到場玩家。所有操作另要求輸入預覽姓名人工核對身份，槽位衝突與非分隊模式受到 Main 阻擋。送出不代表成功或到場，未知結果不重送。尚未取得真實 #UID 樣本；批次佇列、正式 roster／換人政策仍保持 partial。

### 逐步房間與陣容計畫（2026-10-30，#7／#8／#9）

房名與隊伍／計分模式可預覽差異後逐步套用；容量不包含在此計畫，仍使用獨立設定及人工核對。手動陣容可產生移位後分隊的計畫，必須逐人輸入觀測姓名及確認換人政策；未知玩家、缺漏、重複槽位、佔位循環均阻擋。每步以新的 settings／listrefs 及固定連線／房間 epoch 核對，外部結構變更、錯誤、逾時或斷線停止後續步驟；不回滾已觀測效果、不重送未知操作。計畫記錄仍使用最小恢復資料，重啟不重播。

### 手動圖池（2026-10-30，#10）

連續換圖介面可保存／選擇最多 200 個手動槽位，含地圖、room Mods、Freemod 及人工個人規則。Main 在記憶體驗證並管理版本；登出清除，不以 OCLR 圖池名義落盤。單項無效只阻擋該項，其他有效槽位可用。更新圖池會使舊預覽失效，停止尚未送出的圖池步驟，並要求重新套用後才通過相關 Start 核對。正式 OCLR entry 授權與遊戲 ruleset 切換仍待契約／觀測能力。

### Context 候選合成驗證（2026-10-30，#14）

已新增獨立 context schema、Main 純檢查器與注入式唯讀 reader：身分／場次隔離、逐意圖最低檢查、Start 圖／Mods／lineup／政策、人工確認指紋、single-flight、429、過期與撤權清除均有合成測試。尚未接入生產 IPC／HTTP 或衍生執行；正式契約、綁定控制器、#40 場次開房及真實聯調仍待完成。詳見 context 契約末節及 candidate JSON Schema。

### 指令導航補齊（2026-10-30，#12）

有限搜尋 registry 已涵蓋圖池、房間設定、初始化、玩家及陣容表單。搜尋只展開並聚焦既有表單，不呼叫變更 IPC；Cmd／Ctrl+K 與 Escape 保留 composition 保護。新增合成驗證確認全部面板定位、不送指令及小視窗聊天輸入區可見，真實 IME／螢幕閱讀器仍另驗。

### 場次開房候選控制器（2026-10-30，#40）

已用合成 context 與真實 IrcSession 驗證開房預覽、派送前重讀、一次性提交、可信回覆來源追蹤、JOIN 後唯讀查詢、逾時不重送及晚到房間隱私處理。正式 context／授權與日誌 hook 未接入前不註冊產品 IPC／UI，不以既有 panel 直接放行。詳見開房流程文件。

OCLR 場次無法準備指令時，會區分取消、賽果已核准、未開放操作與缺少規則；請依顯示原因回網站核對。完整 context 與場次開房仍是未接入正式 API 的候選核心，不能以唯讀 panel 的可用性視為已授權執行。

房間工作區採精簡頂列：「加入」與「新建」使用 HeroUI 對話框；全高右側工具欄提供操作／玩家分頁、獨立捲動，並以三條線圖示收合／展開。寬視窗可拖曳或用分隔線左右鍵調整欄寬；900×640 自動使用圖示導覽與 280px 工具欄，聊天輸入保持可見。左側五個頁面分別使用插頭、對話框、獎盃、文件及歷史時鐘圖示，滑鼠停留可查看頁面名稱。

「新建」會從目前選取且資料有效的 OCLR 場次帶入已保存房名，並顯示來源場次；可手動修改，但仍需確認既有房間。切換場次、登出或資料失效會清除舊來源並取消確認。此為房名帶入，不代表正式 context 開房／初始化或投影已啟用。

網站輪次規則相容更新（2026-10-30）：支援可選的同隊同 Mod 重複 Ban 設定及 NM/FM 例外，TB 不可 Ban；既有未設此欄位的規則維持相容。此為共享契約／驗證同步，網站仍是保存執裁紀錄的權威，未執行真實 Bancho 聯調。

### 網站直接開房修復（2026-10-31）

IRC 登入後，在 OCLR 場次核對帳號並按「連接網站 IRC」，沒有選取房間且沒有既有／未知開房結果時，會建立只接收開房指令的連線。網站的「傳送至本機 IRC」將 `!mp make` 送給 BanchoBot；本機沿用持久化防重送、可信回覆、JOIN 與設定／裁判查詢。驗證完成後自動切換為該房間投影。未知結果不重送，開房結果仍須在本機核對；網站不冒稱 socket 寫入已成功建立。

面板規則已相容網站的可選 `exPlayersPerTeam`，保留 1–16 或 null 的驗證、本人指派、PKCE 與帳號配對。瀏覽器網站登入與桌面授權仍為獨立 session。

設定位於側欄底部齒輪；原本「轉入背景／退出程式」區塊已移除。背景執行預設開啟以延續既有行為，語言預設跟隨系統。設定只保存背景開關與語言，不保存帳號或聊天。詳見 [應用程式設定](docs/m1/app-settings.md)。

網站執裁頁可按「開啟 OCLR IRC」，以 `oclr-irc://connect?fixture=<UUID>` 帶入場次；請使用最新版封裝程式。桌面登入 IRC 並按「繼續連接」後接續原 OCLR 授權／帳號核對流程。Linux 解壓後另執行成品內的 `install-protocol.sh`。連結不攜帶憑證或自動送指令。詳見 [網站 IRC 投影](docs/m1/website-irc-relay.md)。
